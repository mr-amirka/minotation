# minotation-cli

Команда `mn` — сборка CSS из токенов [minotation](../core) без сборщика.

Нужна там, где сборщика нет или он чужой: статический сайт, шаблоны на PHP,
Go-template, Jinja, генерация CSS в CI, быстрая проверка «что получится из этой
разметки».

```bash
pnpm add -D minotation-cli minotation
```

## Быстрый старт

```bash
mn ./src -o ./dist/app.css
```

Команда обходит путь, находит токены во всех подходящих файлах и пишет один
CSS-файл. Путь по умолчанию — текущая директория, вывод — `./mn.css`.

```bash
mn ./src --watch                        # пересобирать при изменениях
mn ./templates --attrs "class, className:class"   # className тоже даёт классы
mn ./src -p .app                        # префикс у всех селекторов
mn ./index.html -o ./page.css           # одиночный файл
```

## Опции

| Опция | Что делает |
|-------|------------|
| `-o, --output <файл>` | куда писать CSS (по умолчанию `./mn.css`); шаблон с `[name]` (запись `entry`) и `[hash]` (хеш содержимого): `./dist/[name].[hash].css` |
| `-w, --watch` | следить за изменениями и пересобирать |
| `-c, --config <файл>` | файл конфигурации (по умолчанию `./mn.config.js`) |
| `-a, --attrs <список>` | какие атрибуты сканировать и во что разворачивать, как в v1: `"class, className:class"`, `"class, m"` → `[m~="p10"]` (по умолчанию `class`); подробно — [`attrs`](../minotation-build#attrs--какие-атрибуты-сканировать-и-во-что-разворачивать) |
| `-p, --prefix <строка>` | префикс для всех селекторов |
| `--alt-color` | запасное непрозрачное объявление рядом с `rgba` |
| `--strict` | код возврата 1, если встретился битый токен |
| `--no-syntax` | не разбирать JS/TS парсером, только текстовый поиск |
| `--skip-partials` | пропускать файлы-партиалы `_*` |
| `--no-manifest` | не писать `mn-manifest.json` рядом с CSS (по умолчанию пишется: `{ "mn.css": "mn.3f9a1c2e.css" }`) |
| `-m, --metrics <файл>` | записать статистику употребления токенов (JSON) |
| `--include <regexp>` | какие файлы сканировать |
| `--exclude <regexp>` | какие пропускать |
| `-v, --version`, `-h, --help` | версия и справка |

Аргументы командной строки важнее конфига.

### Что сканируется

По умолчанию — `.html`, `.htm`, `.php`, `.vue`, `.svelte`, `.astro`, `.js`,
`.jsx`, `.ts`, `.tsx`, `.mjs`, `.cjs`; не сканируются `node_modules`, `.git`,
`dist`, `build` и сам файл конфигурации. Оба списка перекрываются опциями
`--include` и `--exclude`.

Путь, указанный явно, берётся без фильтра по расширению: `mn ./page.tmpl`
работает, хотя `.tmpl` в списке нет.

Токены ищет `createScanner` из ядра — тот же разбор, что у плагинов для vite,
webpack, rollup, esbuild и astro. Это не деталь реализации, а обязательное
условие: свой разбор в плагине однажды привёл к тому, что токены из переменных
(`classVarSuffixes`) собирались только в vite, а в остальных сборщиках молча
терялись.

### Синтаксический разбор

Файлы JS-семейства (`.js/.jsx/.ts/.tsx/.mjs/.cjs/.mts/.cts`) разбираются
парсером, у однофайловых компонентов (`.vue`, `.svelte`, `.astro`) так
разбирается скриптовая часть, остальное — текстом. Включать ничего не нужно:
способ выбирается по расширению.

Зачем: текстовый поиск не отличает код от того, что на код похоже.

```tsx
const re = /"/;
/** Пример: <div class="p99 w999">…</div> */
export const App = () => <div class="p10 m20" />;
```

```bash
mn ./src -o ./app.css               # 2 токена: p10, m20
mn ./src -o ./app.css --no-syntax   # 4 токена: плюс лишние p99, w999
```

Парсер (`typescript`) — необязательная peer-зависимость. Нет его в проекте —
работает текстовый разбор, молча. Файл с синтаксической ошибкой тоже
откатывается к текстовому: недописанная скобка не повод срывать сборку.

`--no-syntax` нужен там, где `typescript` есть, но тратить на него время
сборки не хочется: разбор примерно в 6 раз дороже текстового поиска
(82 мкс против 13 мкс на файл).

### Статистика употребления

`--metrics` пишет рядом с CSS отчёт: какие токены и сколько раз встретились —
по проекту целиком и по каждому файлу.

```bash
mn ./src -o ./app.css -m ./metrics.json
```

```json
{
  "filesScanned": 2,
  "tokensTotal": 4,
  "occurrences": 6,
  "tokens": [
    { "name": "p10", "count": 3 },
    { "name": "dF", "count": 1 }
  ],
  "files": {
    "src/index.html": [
      { "name": "p10", "count": 2 },
      { "name": "dF", "count": 1 }
    ]
  }
}
```

Списки отсортированы по убыванию частоты, при равной частоте — по имени: две
выгрузки одного проекта можно сравнить построчно.

`tokensTotal` — сколько уникальных токенов уехало в CSS, включая `safelist`;
счётчики в `tokens` считают только встреченное в файлах, поэтому числа могут
расходиться. Файлы без единого токена в отчёт не попадают.

В v1 это были две опции — `--metrics` и `--metricsFiles`, писавшие два файла с
пересекающимся содержимым. Здесь один отчёт: разбивка по файлам лежит внутри.

## Конфиг

```js
// mn.config.js
module.exports = {
  input: './src',
  output: './dist/app.css',
  prefix: '.app',
  attrs: 'class, className:class', // строка, массив или объект — как --attrs
  syntax: false,                  // только текстовый разбор (как --no-syntax)
  metricsPath: './metrics.json',  // то же, что -m
  safelist: ['m20', 'dF'],        // токены, которых нет в разметке
  include: /\.(html|tsx)$/,
  exclude: /[\\/]vendor[\\/]/,
  presets: [/* свои пресеты вместо стандартного набора */],
  mn: {/* остальные опции ядра */},
  skipPartials: true,             // как --skip-partials
  manifest: './dist/css.json',    // свой путь манифеста; false — как --no-manifest
};
```

Несколько CSS из одного прохода — записи `entry`; в `output` тогда нужен `[name]`:

```js
module.exports = {
  input: './src',
  output: './dist/[name].[hash].css',
  entry: {
    site: { include: /src\/site\// },
    admin: { include: /src\/admin\//, mn: { selectorPrefix: '.admin ' } },
  },
};
```

Отсутствие конфига — не ошибка: всё задаётся опциями. А вот существующий, но
битый конфиг обрывает работу с кодом 1 — собрать не то, что просили, хуже, чем
не собрать ничего.

Конфиг читается обычным `require`, поэтому годятся `.js` (CommonJS), `.cjs` и
`.json`, а начиная с Node 22.12 — и ESM. На более старых Node в проекте с
`"type": "module"` конфиг нужно назвать `mn.config.cjs`.

## Коды возврата

| Код | Когда |
|-----|-------|
| 0 | CSS собран |
| 1 | неизвестная опция, нечитаемый конфиг или — с `--strict` — битый токен |

Без `--strict` битые токены печатаются предупреждением, но сборку не роняют:
чужие классы в разметке (`sr-only`, `mt-auto`) — обычное дело.

## Из кода

То же самое доступно как библиотека — когда компиляция встроена в собственный
скрипт сборки:

```js
const { compile } = require('minotation-cli');

const { css, files, tokens, warnings } = compile({
  input: './src',
  prefix: '.app',
});
```

## Чего здесь нет

**Инкрементальной пересборки.** CSS собирается из объединения токенов всех
файлов, поэтому удаление токена из одного файла всё равно потребовало бы
пересчёта целиком. Полный проход по типичному проекту занимает единицы
миллисекунд.

**Зависимостей.** Ни `commander`, ни `chokidar`: команду ставят ради одной
задачи, и тянуть за собой дерево пакетов незачем. Разбор аргументов —
сто строк в [`args.ts`](src/args.ts), наблюдение — `fs.watch`.
