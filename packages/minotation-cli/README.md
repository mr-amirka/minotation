# minotation-cli

Команда `mn` — сборка CSS из токенов [minotation](../core) без сборщика.

Нужна там, где сборщика нет или он чужой: статический сайт, шаблоны на PHP,
Go-template, Jinja, генерация CSS в CI, быстрая проверка «что получится из этой
разметки».

```bash
pnpm add -D minotation-cli minotation
```

## Быстрый старт

```bash
mn ./src -o ./dist/app.css
```

Команда обходит путь, находит токены во всех подходящих файлах и пишет один
CSS-файл. Путь по умолчанию — текущая директория, вывод — `./mn.css`.

```bash
mn ./src --watch                        # пересобирать при изменениях
mn ./templates --attrs "class, className:class"   # className тоже даёт классы
mn ./src -p .app                        # префикс у всех селекторов
mn ./index.html -o ./page.css           # одиночный файл
```

### Варианты и состояния — без выбора классов в JS

Токены в `className` — только статические строки; вариант — обычный класс на элементе, а
зависящие от него токены уточнены им в записи:

```tsx
<div className={`dF aiC (fx1|o0.5).transition (bg1D2A4D|cF).splash ${variant}`} />   // ✅
<div className={variant === 'splash' ? 'bg1D2A4D cF' : 'fx1 o0.5'} />                 // ✅ тоже: ветви — литералы
<div className={clsx({ 'bg1D2A4D cF': splash })} />                                   // ❌ токенов не будет в CSS
```

Сканер читает литералы, а не исполняет код. Литералы, которые могут стать значением, он берёт
(ветви `?:`, правая часть `&&`, обе части `||`/`??`); аргументы `clsx(...)` и склейку имён токенов
(`'bg' + color`) — нет: сборка зелёная, стилей нет. Запись с уточнением классом всё равно лучше:
она одна на N вариантов, а состояние видно в разметке. Подробно, с примерами (несколько вариантов, состояния
`.active`/`.disabled`, `data-*` и ARIA, состояние родителя, медиа): [core README — «Варианты и
состояния без JS»](../core/README.md#варианты-и-состояния-без-js).

## Опции

| Опция | Что делает |
|-------|------------|
| `-o, --output <файл>` | куда писать CSS (по умолчанию `./mn.css`); шаблон с `[name]` (запись `entry`) и `[hash]` (хеш содержимого): `./dist/[name].[hash].css` |
| `-w, --watch` | следить за изменениями и пересобирать |
| `-c, --config <файл>` | файл настроек (по умолчанию `./minotation.config.{js,cjs,mjs,json}` — общий с плагинами, D-081) |
| `-a, --attrs <список>` | какие атрибуты сканировать и во что разворачивать, как в v1: `"class, className:class"`, `"class, m"` → `[m~="p10"]` (по умолчанию `class`); подробно — [`attrs`](../minotation-build#attrs--какие-атрибуты-сканировать-и-во-что-разворачивать) |
| `--alt-color` | запасное непрозрачное объявление рядом с `rgba` |
| `--warning-mode <режим>` | что делать с предупреждением о битом токене: `log` — напечатать (по умолчанию), `silent` — промолчать, `error` — код возврата 1 |
| `--specificity-mode <режим>` | токены с накруткой специфичности (`f10*2`): `warn` — предупреждение с подсказкой (по умолчанию), `silent` — промолчать, `strict` — токен не даёт CSS, код возврата 1 |
| `--important-mode <режим>` | токены с `!important` (`f10-i`) — режимы те же |
| `--child-selector-mode <режим>` | токены с дочерним селектором `>` (`cF00>1`) — режимы те же |
| `--unknown-media-mode <режим>` | неизвестное имя медиа (`p10@zz`) — режимы те же (D-058) |
| `--suspect-class-mode <режим>` | класс другой CSS-системы (`fw-bold`) — режимы те же (D-065) |
| `--handler-conflict-mode <режим>` | одно имя от двух пресетов — режимы те же (D-067) |
| `--preset-conflict-mode <режим>` | пресеты несовместимых экосистем — режимы те же (D-067) |
| `--group-suspect-mode <режим>` | группа скобок даёт битый CSS (`cF:is(.a\|.b)`) — режимы те же (D-077) |
| `--group-mode <groups\|css>` | `css` — скобки как в CSS, без групп `(a\|b)` (D-077) |
| `--notation-conflict-mode <режим>` | класс в файлах с разными режимами синтаксиса значит разное: `warn` (по умолчанию) или `strict` |
| `--context-where` | контекст селектора в `:where()`: специфичность только у класса, как в Tailwind v4 |
| `--media-nesting` | вложенные `@media` вместо `and` (D-070) |
| `--notation-mode <режим>` | синтаксис классов: `context-qualified` (по умолчанию, `bg-blue-500:hover@md`), `tw4-compatible` (как Tailwind, `md:hover:bg-blue-500`) `breakpoint-prefixed` (как quantum-css, `SM_px15`) или `property-value` (как Master CSS, `bg:blue:hover@md`) |
| `--no-syntax` | не разбирать JS/TS парсером, только текстовый поиск |
| `--skip-partials` | пропускать файлы-партиалы `_*` |
| `--no-manifest` | не писать `mn-manifest.json` рядом с CSS (по умолчанию пишется: `{ "mn.css": "mn.3f9a1c2e.css" }`) |
| `-m, --metrics <файл>` | куда писать статистику употребления токенов (по умолчанию `mn-metrics.json` рядом с CSS) |
| `--no-metrics` | не писать статистику |
| `--include <regexp>` | какие файлы сканировать |
| `--exclude <regexp>` | какие пропускать |
| `-v, --version`, `-h, --help` | версия и справка |

Аргументы командной строки важнее конфига.

### Что сканируется

По умолчанию — `.html`, `.htm`, `.php`, `.vue`, `.svelte`, `.astro`, `.js`,
`.jsx`, `.ts`, `.tsx`, `.mjs`, `.cjs`; не сканируются `node_modules`, `.git`,
`dist`, `build` и сам файл конфигурации. Оба списка перекрываются опциями
`--include` и `--exclude`.

Путь, указанный явно, берётся без фильтра по расширению: `mn ./page.tmpl`
работает, хотя `.tmpl` в списке нет.

Токены ищет `createScanner` из ядра — тот же разбор, что у плагинов для vite,
webpack, rollup, esbuild и astro. Это не деталь реализации, а обязательное
условие: свой разбор в плагине однажды привёл к тому, что токены из переменных
(`classVarSuffixes`) собирались только в vite, а в остальных сборщиках молча
терялись.

### Синтаксический разбор

Файлы JS-семейства (`.js/.jsx/.ts/.tsx/.mjs/.cjs/.mts/.cts`) разбираются
парсером, у однофайловых компонентов (`.vue`, `.svelte`, `.astro`) так
разбирается скриптовая часть, остальное — текстом. Включать ничего не нужно:
способ выбирается по расширению.

Зачем: текстовый поиск не отличает код от того, что на код похоже.

```tsx
const re = /"/;
/** Пример: <div class="p99 w999">…</div> */
export const App = () => <div class="p10 m20" />;
```

```bash
mn ./src -o ./app.css               # 2 токена: p10, m20
mn ./src -o ./app.css --no-syntax   # 4 токена: плюс лишние p99, w999
```

Парсер (`typescript`) — необязательная peer-зависимость. Нет его в проекте —
работает текстовый разбор, молча. Файл с синтаксической ошибкой тоже
откатывается к текстовому: недописанная скобка не повод срывать сборку.

`--no-syntax` нужен там, где `typescript` есть, но тратить на него время
сборки не хочется: разбор примерно в 6 раз дороже текстового поиска
(82 мкс против 13 мкс на файл).

### Статистика употребления

Рядом с CSS пишется `mn-metrics.json`: какие токены и сколько раз встретились —
по проекту целиком и по каждому файлу. `-m` задаёт свой путь, `--no-metrics`
отключает отчёт.

```bash
mn ./src -o ./app.css -m ./metrics.json
```

```json
{
  "filesScanned": 2,
  "tokensTotal": 4,
  "occurrences": 6,
  "tokens": [
    { "name": "p10", "count": 3 },
    { "name": "dF", "count": 1 }
  ],
  "files": {
    "src/index.html": [
      { "name": "p10", "count": 2 },
      { "name": "dF", "count": 1 }
    ]
  }
}
```

Списки отсортированы по убыванию частоты, при равной частоте — по имени: две
выгрузки одного проекта можно сравнить построчно.

`tokensTotal` — сколько уникальных токенов встретилось в файлах. Файлы без единого токена в
отчёт не попадают.

В v1 это были две опции — `--metrics` и `--metricsFiles`, писавшие два файла с
пересекающимся содержимым. Здесь один отчёт: разбивка по файлам лежит внутри.

## Конфиг

Файл `minotation.config.*` в рабочем каталоге — **общий для CLI и всех плагинов** (D-081): CLI берёт
из него свои опции, опции других инструментов (`fileName`, `inject`) пропускает.

```js
// minotation.config.js
module.exports = {
  input: './src',
  output: './dist/app.css',
  altColor: true,                 // как --alt-color
  attrs: 'class, className:class', // строка, массив или объект — как --attrs
  syntax: false,                  // только текстовый разбор (как --no-syntax)
  metrics: './metrics.json',      // то же, что -m; false — как --no-metrics
  include: /\.(html|tsx)$/,
  exclude: /[\\/]vendor[\\/]/,
  presets: [/* свои пресеты вместо стандартного набора */],
  altColor: true,                 // как --alt-color
  warningMode: 'error',           // как --warning-mode error
  specificityMode: 'strict',      // как --specificity-mode strict: f10*2 — ошибка
  importantMode: 'silent',        // как --important-mode silent
  maxDepth: 3,                    // предел глубины <N/>N; maxDepthMode — как specificityMode
  media: { wide: { query: '(min-width: 1200px)' } },
  skipPartials: true,             // как --skip-partials
  manifest: './dist/css.json',    // свой путь манифеста; false — как --no-manifest
};
```

Несколько CSS из одного прохода — записи `entry`; в `output` тогда нужен `[name]`:

```js
module.exports = {
  input: './src',
  output: './dist/[name].[hash].css',
  entry: {
    site: { include: /src\/site\// },
    admin: { include: /src\/admin\//, altColor: true },
  },
};
```

Отсутствие конфига — не ошибка: всё задаётся опциями. А вот существующий, но
битый конфиг обрывает работу с кодом 1 — собрать не то, что просили, хуже, чем
не собрать ничего. То же с опечаткой и значением не того типа:

```
Error: [minotation] minotation.config.js: unknown option "altColour". Did you mean "altColor"?
Error: [minotation] minotation.config.js: option "metrics" expects a boolean or a string, got number 1
```

Опции плагинов, которых у CLI нет (`fileName`, `root`, `extensions`, `inject`, …), в файле допустимы —
он общий; CLI их не использует. Опечатка в любом ключе — ошибка.

Конфиг читается обычным `require`, поэтому годятся `.js` (CommonJS), `.cjs` и
`.json`, а начиная с Node 22.12 — и ESM. На более старых Node в проекте с
`"type": "module"` файл нужно назвать `minotation.config.cjs`.

## Коды возврата

| Код | Когда |
|-----|-------|
| 0 | CSS собран |
| 1 | неизвестная опция, нечитаемый конфиг, с `--warning-mode error` — битый токен, в режиме `strict` — запрещённый токен (`*N`, `-i`, глубина) |

Без `--warning-mode error` битые токены печатаются предупреждением, но сборку не роняют:
чужие классы в разметке (`sr-only`, `mt-auto`) — обычное дело.

## Из кода

То же самое доступно как библиотека — когда компиляция встроена в собственный
скрипт сборки:

```js
const { compile } = require('minotation-cli');

const { css, files, tokens, warnings } = compile({
  input: './src',
  altColor: true,                 // как --alt-color
});
```

## Чего здесь нет

**Инкрементальной пересборки.** CSS собирается из объединения токенов всех
файлов, поэтому удаление токена из одного файла всё равно потребовало бы
пересчёта целиком. Полный проход по типичному проекту занимает единицы
миллисекунд.

**Зависимостей.** Ни `commander`, ни `chokidar`: команду ставят ради одной
задачи, и тянуть за собой дерево пакетов незачем. Разбор аргументов —
сто строк в [`args.ts`](src/args.ts), наблюдение — `fs.watch`.
