# minotation-gulp

Gulp-плагин [minotation](../core): собирает токены из файлов пайпа и отдаёт
готовый CSS отдельным файлом в тот же поток.

```bash
pnpm add -D minotation minotation-build minotation-gulp
```

## Быстрый старт

```js
const gulp = require('gulp');
const { mnGulp } = require('minotation-gulp');

exports.css = () => gulp.src('src/**/*.html')
  .pipe(mnGulp({ fileName: 'app.css' }))
  .pipe(gulp.dest('dist'));
```

Исходные файлы проходят насквозь без изменений — их забирает `gulp.dest`,
как обычно. В конце пайпа появляется ещё один файл, с собранным CSS.

## Опции

| Опция | По умолчанию | Что делает |
|-------|--------------|------------|
| `fileName` | `'mn.css'` | имя CSS-файла, который уходит в поток |
| `attr` | `'class'` | атрибут, в котором ищутся токены |
| `classVarSuffixes` | `['Class']` | суффиксы имён переменных со списком токенов |
| `mergeFnNames` | `['mne', 'mnClass']` | функции слияния, чьи строковые аргументы сканируются |
| `syntax` | авто | разбор JS/TS парсером; по умолчанию выбирается по расширению |
| `safelist` | `[]` | токены, нужные всегда |
| `presets` | стандартный набор | пресеты компиляции |
| `exclude` | — | какие файлы пайпа не сканировать (по пути) |
| `mn` | — | опции mn-инстанса: `selectorPrefix`, `media`, `strict`, `onWarning` |

Сканирование и компиляция — общие с остальными интеграциями
([`minotation-build`](../minotation-build)), поэтому `.tsx` здесь разбирается
парсером ровно так же, как в vite или webpack.

## Два отличия от версии 1.x

**CSS уходит в поток, а не пишется на диск.** В 1.x плагин звал `writeFile`
сам, а путь назначения был первым аргументом: `gulpMN('./dist/app.css', …)`.
Для gulp это чужеродно — там поток трансформируют, а записью занимается
`gulp.dest()`. Своя запись вдобавок игнорировала всё, что стоит дальше по
пайпу: `gulp.dest`, `gulp-rename`, плагины минификации.

**Файлы, чьё имя начинается с `_`, больше не пропускаются.** В 1.x такие файлы
молча выбрасывались — заимствование из Sass, где `_partial.scss` означает «не
компилировать отдельным файлом». Для сканера токенов аналогия не работает:
партиал включается в страницу, его классы окажутся в DOM, а правил для них не
будет — и тоже молча. Кому нужно прежнее поведение:

```js
mnGulp({ exclude: /(^|[\\/])_/ })
```

## Что делает плагин с необычными файлами

| Файл | Поведение |
|------|-----------|
| директория (`isNull`) | проходит насквозь |
| поток (`gulp.src(…, { buffer: false })`) | проходит насквозь: прочитать его здесь нечем |
| подпадает под `exclude` | проходит насквозь, но токены из него не берутся |

Если токенов не нашлось ни одного и пресеты ничего не дали, CSS-файл в поток
не добавляется — иначе `gulp.dest` создал бы пустой файл, а в разметке
появилась бы ссылка на него.

## Предупреждения

Битые токены печатаются через `console.warn` с префиксом `[minotation]`: у
gulp нет отдельного канала предупреждений, вывод задачи — он и есть.
`mn: { onWarning: 'silent' }` их гасит, своя функция вызывается как есть.
